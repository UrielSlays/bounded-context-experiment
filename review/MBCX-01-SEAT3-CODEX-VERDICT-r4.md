## 8. Attacks A–H

### Attack A — strongest-flat challenge

**Input:** One synthetic trace covered every required transition family. Synthetic IDs included `OC, OP, OD, OU, UX, D0–D3, XS, OT, ON`.

**Method:** An in-memory journal reducer performed ordered replay, current flat projection, tombstone suppression, reverse prerequisite activation, bounded BFS, cross-scope selection, terminal filtering, and near-due selection. A parallel typed projection was constructed from the same events.

**Output:**

- F+ and TN produced the same canonical current state: `state.color = red`.
- Canonical obligation statuses were:

  `OC=open, OP=completed, OD=open, OU=open, UX=open, D3=completed, D2=completed, D1=completed, D0=open, XS=open, OT=completed, ON=open`.

- Both selectors chose: `D0, OC, OD, ON, OU, XS`.
- Closures: `D0→[D1,D2,D3]`, `OD→[OP]`; the remaining selected items had empty closures.
- Cheap journal replay additionally derived:

  - currentness: `e1=true`, `e2=false`
  - supersession: `e2→e1`
  - restoration: `e3→e1`
  - lifecycle status
  - provenance: `[e1,e2,e3]`

**Interpretation:** F+ need not persist typed objects to expose these facts. Primitive operation names such as `correct`, `retract`, and `cancel`, plus public target IDs, already encode enough structure for deterministic projection.

**Limitation:** Because r3 omits the actual transition table, this was a declared proxy algebra, not certification against the missing official semantics.

### Attack B — render-matched control

**World:**

1. `p1`: assert deadline `2026-08-15`
2. `p2`: correct `p1` to `2026-08-16`
3. `p3`: assert deadline `2026-08-17`
4. `p4`: retract `p2`
5. Available actions: resolve/escalate conflict, commit `p1`, commit `p3`

**Exact logical packets used:**

| Arm | Logical contents |
|---|---|

| FM | Same TN outer fields; current row `2026-08-17`; `versions=[]`, `conflicts=[]`, `supersession=[]`, `validity=[]`, `provenance=[]` |
| TF | Flat rendering of active candidates `p1,p3`; public relations `p2 corrects p1`, `p4 retracts p2` |
| TN | `unresolved_conflict`; versions `p1 current`, `p2 non-current/retracted`, `p3 current`; candidates `p1,p3`; supersession `p2→p1`; provenance `p1…p4` |

Canonical proxy JSON sizes were:

- F+: 445 bytes
- FM: 236 bytes
- TF: 232 bytes
- TN: 472 bytes

TN therefore carried 236 more bytes than FM in this fixture.

**False TN win:** The flat journal can derive that retracting `p2` restores `p1`, leaving `p1` and `p3` in unresolved conflict. FM is nevertheless required to emit empty conflict/currentness fields. TN gets exclusive decision-relevant information without an exclusive cheap mechanism.

**False TN loss:** TN may carry irrelevant versions, evidence references, and relations that consume attention or token headroom while FM receives empty placeholders.

**Ruling:** FM is typography-matched, but not information-, resolver-, density-, or salience-matched. `TN−FM` is not the correct primary contrast.

This is consistent with StateFuse’s use of strong matched flat/multi-value controls and projection-based materialization, where strong flat baselines can tie typed approaches rather than automatically lose ([StateFuse paper](https://arxiv.org/html/2607.05844), [official repository](https://github.com/nZiben/statefuse)). *Presentation, Not Mechanism* supports render matching but does not justify calling a deliberately information-blinded render control the strongest flat mechanism ([paper](https://arxiv.org/html/2607.16019)).

## 9. WHAT WOULD YOU BUILD?

I would build a corrected disposable instrument with three prior-to-inference gates:

1. **Executable semantic algebra.** Freeze a complete transition table, precedence rules, and gold generator. Exhaustively enumerate small traces and run property tests over correction/retraction, conflict, restoration, cancellation, and dependency transitions.

2. **Strong flat-derived comparator (`FD`).** Persist only the primitive append-only journal and cheap indexes, but derive every public-reconstructible currentness, conflict, restoration, supersession, and evidence relation at projection time. Render FD and TN through the same schema, selector, ordering, relevance policy, object caps, and byte budget.

   - If FD and TN packets are semantically identical, do not spend model calls pretending there is an information treatment. Compare persistence size, update/read latency, reconstruction reliability, and bounded-compute cost.
   - If TN exposes information FD cannot derive within a frozen cheap-compute budget, isolate and declare that exact residual before inference.

3. **Satisfiable scored universe.** Define the complete available action set at every step and score every exposure mechanically. Generate exact class quotas as stratification constraints, not as totals that contradict the action list.

Before pilot, I would run a SAT/enumerator gate proving:

- Every legal scenario satisfies all count and cardinality constraints.
- Every output field has one validation and scoring rule.
- Every legal transition has one canonical result.
- Every maximum fixture fits the exact target tokenizer.
- The selected `n` passes the declared OC claim over the claim’s actual distribution domain.
- A complete cost envelope fits the owner’s maximum spend.

The direct prior-art mechanism to borrow is StateFuse’s strong flat/multi-value comparator with projection-time materialization and a matched resolver—not its conclusion as a universal guarantee. I would also borrow Mem2Act’s no-memory-discriminator idea for testing history necessity ([Mem2Act](https://arxiv.org/html/2601.19935v1)).

## 10. WOULD YOU DESIGN IT DIFFERENTLY?

**YES.**

The present design treats “typed information hidden from FM” as evidence for typed persistence. I would instead separate:

- persisted representation,
- deterministic projection capability,
- exposed semantic information,
- render/layout,
- resolver policy,
- token budget,
- compute/update/reconstruction cost.

Paid action scoring should occur only where two arms genuinely differ after those dimensions are matched. Otherwise the cheaper and more decisive Stage-A result is deterministic equivalence plus engineering cost.

## 11. Omission attack

- **Strong simple comparator omitted:** Flat append-only log plus bounded projection-time derivation of currentness, conflicts, supersession, restoration, validity, and provenance, rendered in the exact TN schema.
- **Hidden confound favoring FM:** Empty typed fields make FM shorter and less cluttered, leaving more attention/token headroom than TN.
- **Hidden confound favoring TN:** FM is prohibited from exposing journal-derivable conflict/restoration facts while TN receives them explicitly; the 75% generator-A mixture may also reflect the typed ontology.
- **Persuasive false positive:** A retracted correction restores an older assertion beside a conflicting newer assertion. TN labels the unresolved conflict; FM must leave conflict fields empty. The model chooses the safe escalation only under TN, producing an apparent architecture gain that a cheap flat projection would also achieve.
- **Persuasive false kill:** TN serializes irrelevant versions, relations, and provenance near the payload cap, crowding a near-due obligation that FM retains because its typed fields are empty.
- **Uncaught footgun:** The 48–64 step/action-cardinality rules require at least 192 action exposures while the scorer asserts that 60 are complete.
- **No-paid test required before pilot:** A constraint/SAT enumerator proving workload counts, action-universe completeness, output scoring, and maximum-fixture feasibility. I would refuse pilot inference without it.
- **Mechanism to borrow:** StateFuse-style strong flat projection/multi-value exposure under the same resolver and downstream budget.
- **Machinery to delete:** Paid 25% F+/TF/status diagnostics until deterministic FD/TN packet parity and a diagnostic precision requirement exist.
